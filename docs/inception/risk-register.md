# Risk Register

| ID | Riesgo | Categoria | Probabilidad | Impacto | Mitigacion | Contingencia |
|----|--------|-----------|-------------|---------|------------|-------------|
| **R01** | Baja adopcion por administradores de clubes (resistencia al cambio desde herramientas manuales) | Negocio | Alta | Alto | UX de onboarding simplificado, periodo de prueba extendido, importacion masiva de datos desde CSV/Excel, material educativo (tutoriales, webinars) | Plan de incentivos para early adopters (3 meses gratis Premium), success managers para clubes piloto |
| **R02** | Gamificacion percibida como "infantil" o no alineada con el publico objetivo adulto | Negocio | Media | Alto | Diseno de gamificacion serio y profesional (no "juego"), insignias con significado deportivo real, validacion UX con usuarios reales antes del desarrollo completo | Encuestas de satisfaccion continuas, iteracion rapida en mecanicas de gamificacion basada en feedback |
| **R03** | APIs de wearables (Strava, Garmin) cambian sus terminos o restringen acceso | Externo | Media | Medio | Diseno con capa de abstraccion para integraciones, contratos con proveedores si es viable, monitoreo de cambios en APIs | Funcionalidad offline con input manual de datos deportivos, busqueda de integraciones alternativas |
| **R04** | Fuga de datos personales o brecha de seguridad | Tecnico | Baja | Critico | Arquitectura de seguridad zero-trust, cifrado en reposo y en transito, auditorias de seguridad trimestrales, OWASP Top 10 compliance, penetration testing externo | Plan de respuesta a incidentes documentado, equipo de respuesta 24/7, comunicacion transparente a usuarios, backups inmutables |
| **R05** | Rendimiento deficiente ante picos de carga (ej. durante torneos con muchos check-ins simultaneos) | Tecnico | Media | Alto | Arquitectura cloud-native con auto-scaling, CDN para contenido estatico, cacheo agresivo (Redis), pruebas de carga antes de cada release | Degradacion graceful de funcionalidades no criticas bajo carga extrema, circuit breakers, rate limiting |
| **R06** | Complejidad del modelo de dominio genera deuda tecnica temprana | Tecnico | Alta | Medio | DDD estricto con bounded contexts bien definidos, arquitectura limpia, code reviews obligatorios, refactors programados cada 3 sprints | Refactorizacion priorizada de bounded contexts problematicos, documentacion de decisiones de diseno (ADR) |
| **R07** | Falta de PMF (Product-Market Fit) en segmento objetivo (comunidades pequeñas no pagan) | Negocio | Alta | Critico | Modelo freemium con valor real en capa gratuita, entrevistas continuas con usuarios, metricas de engagement y retencion como indicadores tempranos | Pivot hacia modelo B2B-first (enfocado en clubes medianos/grandes), ajuste de pricing y features |
| **R08** | Costos cloud superan presupuesto por arquitectura no optimizada | Financiero | Media | Alto | Serverless y servicios managed para reducir costos fijos, auto-scaling con limites de presupuesto, alertas de billing en tiempo real, arquitectura revisada por FinOps | Reduccion de features en capa gratuita, plan de optimizacion de costos cloud trimestral |
| **R09** | Dependencia de un proveedor cloud unico (vendor lock-in) | Tecnico | Baja | Medio | Diseno cloud-agnostic (contenedores Docker, Kubernetes), abstracciones de servicios cloud, evitando servicios propietarios cuando exista alternativa open-source | Plan de migracion multi-cloud documentado, evaluacion de alternativas anualmente |
| **R10** | Regulaciones de proteccion de datos (GDPR) cambian o se endurecen en jurisdicciones clave | Externo | Baja | Medio | Privacy-by-design desde el inicio, cifrado y anonimizacion configurables, delegado de proteccion de datos (DPO) externo, auditorias de cumplimiento | Ajustes de compliance en sprints dedicados, funcionalidad de borrado/anonymizacion de datos granulares |
| **R11** | Rotacion de personal clave del equipo de desarrollo | Operativo | Media | Alto | Documentacion exhaustiva (ADRs, wiki, code comments), pair programming rotativo, bus factor minimo 2 por modulo, plan de onboarding documentado | Consultoria externa de emergencia, knowledge transfer sessions grabadas, contratacion proactiva |
| **R12** | Fraude en sistema de puntos/economia virtual (farming de XP) | Tecnico / Negocio | Media | Medio | Validacion antifraude en eventos (geolocalizacion, QR), limites diarios de XP, algoritmos de deteccion de patrones anomalos, auditoria de transacciones | Rollback de puntos fraudulentos, bans temporales/permanentes, ajuste de reglas de economia |
